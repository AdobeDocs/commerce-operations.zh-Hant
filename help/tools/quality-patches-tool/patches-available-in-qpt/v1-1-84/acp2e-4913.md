# ACP2E-4913：資料庫死結後，不會重試REST API出貨與發票建立

ACP2E-4913修補程式修正了透過REST API建立出貨或發票時，因作業未重試而發生資料庫死鎖而永久失敗的問題。 安裝[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84時，即可使用此修補程式。 修補程式ID為ACP2E-4913。 請注意，此問題已排程在Adobe Commerce 2.4.10中修正。

## 受影響的產品和版本

**已為Adobe Commerce版本建立修補程式：**

* Adobe Commerce （所有部署方法） 2.4.8-p3

**與Adobe Commerce版本相容：**

* Adobe Commerce （所有部署方法） 2.4.7 - 2.4.8-p5

>[!NOTE]
>
>此修補程式可能適用於發行版本為[!DNL Quality Patches Tool]的其他版本。 若要檢查修補程式是否與您的Adobe Commerce版本相容，請將`magento/quality-patches`套件更新至最新版本，並在[[!DNL Quality Patches Tool]上檢查相容性：搜尋修補程式頁面](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=zh-Hant)。 使用修補程式ID作為搜尋關鍵字，以尋找修補程式。

## 問題

當發生資料庫死結時，透過REST API建立出貨或商業發票會因為作業未重試而永久失敗。

<u>要再現的步驟</u>：

1. 準備可出貨的多個訂單，以及可開立商業發票的多個訂單。
1. 針對這些訂單並行傳送數個`POST /rest/V1/order/<orderId>/ship`請求，因為整合可能會負載不足。
1. 以相同方式同時傳送數個`POST /rest/V1/order/<orderId>/invoice`要求。
1. 檢查API回應和`var/log/exception.log`。

<u>預期結果</u>：

在死結之後，會重試作業，並建立出貨或商業發票。

<u>實際結果</u>：

部分要求會因下列死結錯誤而失敗。 尚未建立出貨或商業發票，您必須手動建立：

```
SQLSTATE[40001]: Serialization failure: 1213 Deadlock found when trying to get lock; try restarting transaction
```
