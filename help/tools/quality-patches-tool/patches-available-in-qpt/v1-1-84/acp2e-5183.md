# ACP2E-5183：靜態內容部署在具有`@magento_import`的PHP 8.5上失敗

ACP2E-5183修補程式修正了PHP 8.5上靜態內容部署失敗的問題，錯誤為&#x200B;*當模組`LESS`檔案使用`@magento_import`指示詞時，不建議使用null作為陣列位移*。 安裝[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84時，即可使用此修補程式。 修補程式ID為ACP2E-5183。 請注意，此問題已排程在Adobe Commerce 2.4.10中修正。

## 受影響的產品和版本

**已為Adobe Commerce版本建立修補程式：**

* Adobe Commerce （所有部署方法） 2.4.9

**與Adobe Commerce版本相容：**

* Adobe Commerce （所有部署方法） 2.4.4 - 2.4.9

>[!NOTE]
>
>此修補程式可能適用於發行版本為[!DNL Quality Patches Tool]的其他版本。 若要檢查修補程式是否與您的Adobe Commerce版本相容，請將`magento/quality-patches`套件更新至最新版本，並在[[!DNL Quality Patches Tool]上檢查相容性：搜尋修補程式頁面](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=zh-Hant)。 使用修補程式ID作為搜尋關鍵字，以尋找修補程式。

## 問題

PHP 8.5上的靜態內容部署失敗，錯誤為&#x200B;*當模組`LESS`檔案使用`@magento_import`指示詞時，不建議使用null做為陣列位移*。

<u>必要條件</u>：

已安裝PHP 8.5。

<u>要再現的步驟</u>：

1. 啟用自訂模組，提供包含自訂電子郵件內文樣式和`@magento_import`指示詞的`email-inline.less`檔案。
1. 移除靜態內容和產生的檔案：

   ```
   rm -rf pub/static/frontend/* var/view_preprocessed/* generated/code/*
   ```

1. 使用精簡策略執行靜態內容部署：

   ```
   bin/magento setup:static-content:deploy --ansi --no-interaction -f -s compact --jobs 4 --no-html-minify
   ```

<u>預期結果</u>：

靜態內容部署成功完成，並為模組提供的`LESS`檔案產生編譯的CSS。

<u>實際結果</u>：

編譯模組提供的`email-inline.less`檔案與報表時，靜態內容部署中止：

```
Deprecated Functionality: Using null as an array offset is deprecated, use an empty string instead in <magento_root>/vendor/magento/framework/Component/ComponentRegistrar.php on line 71
```
