# ACP2E-5122：已處理的GraphQL購物車錯誤未正確寫入例外記錄檔

ACP2E-5122修補程式修正了已處理的GraphQL購物車請求錯誤會寫入例外記錄檔作為應用程式錯誤的問題。 安裝[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84時，即可使用此修補程式。 修補程式ID為ACP2E-5122。 請注意，此問題已排程在Adobe Commerce 2.4.10中修正。

## 受影響的產品和版本

**已為Adobe Commerce版本建立修補程式：**

* Adobe Commerce （所有部署方法） 2.4.8-p5

**與Adobe Commerce版本相容：**

* Adobe Commerce （所有部署方法） 2.4.4 - 2.4.9

>[!NOTE]
>
>此修補程式可能適用於發行版本為[!DNL Quality Patches Tool]的其他版本。 若要檢查修補程式是否與您的Adobe Commerce版本相容，請將`magento/quality-patches`套件更新至最新版本，並在[[!DNL Quality Patches Tool]上檢查相容性：搜尋修補程式頁面](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html)。 使用修補程式ID作為搜尋關鍵字，以尋找修補程式。

## 問題

已處理的GraphQL購物車請求錯誤會寫入例外記錄檔作為應用程式錯誤。

<u>要再現的步驟</u>：

1. 傳送含無效、過期或已損毀遮罩式購物車ID的GraphQL `placeOrder`變異，例如這個變異：

   ```
       mutation {
           placeOrder(input: { cart_id: "test" }) {
               orderV2 {
                   id
                   number
               }
           }
       }
   ```

1. 檢查GraphQL回應。
1. 檢查`var/log/exception.log`購物車錯誤。

<u>預期結果</u>：

1. GraphQL要求針對不含&#x200B;*HTTP 500*&#x200B;回應的無效購物車，傳回已處理的使用者端對錯誤裝載。
1. 已處理的&#x200B;*GraphQlNoSuchEntityException*&#x200B;未寫入至`var/log/exception.log`，而是被路由至嚴重性較低的記錄通道。

<u>實際結果</u>：

每個要求都會將已處理的例外狀況以`report.ERROR`嚴重性寫入`var/log/exception.log`，這會導致在重複要求期間記錄成長無限制。
